# Bitter Lesson sort, slice 0: alternatives to the sort

The question each alternative answers: how should Memento tell which of its parts a better model would make unnecessary, so their review can be planned and their removal tested?

Evidence: the census (`finding-exercise-census-2026-10-03.md`), the longitudinal view across model generations (`finding-longitudinal-evidence-2026-10-03.md`), the registry, the stage rule and failure history in KILLED_MECHANISMS. One limit applies to every option alike: being exercised shows a part is done, which under governance includes compliance and enforcement, so it is weak evidence of need.

**Model generations.** Telemetry dates each model's arrival in each estate (see the longitudinal finding). Across the Opus line, sessions run further on one instruction. At the switch from Opus 5 to Opus 5.5 in rooms product sessions, playbook reads fell by about two thirds. Plans written, review spawns and working-context edits each rose two- to fourfold, and approvals per prompt held steady. Fable sessions spawn heavily and draw more pauses from the User; Fable may have been chosen for heavier work, so its figures can mix model with work type. Samples are small, and the switches coincide with the passage of time.

## A. Three kinds, as proposed

Parts that make up for current model capability; parts that hold the record; parts that keep authority with the User. The first kind gets retirement criteria.

- **For:** each kind maps to one review action (retirement criteria; keep; held by the User). Its first kind can include restart and compaction by right: the context window and the stateless session are model properties that improve, so those parts may fade too, on a longer clock.
- **Against:** the census shows playbooks fading while restart, planning and routing are exercised; one criterion and one review date would suit neither group's clock.
- **What would show it wrong:** at a census re-run after a model generation change, corrected for activity and compliance, units sorted as compensating separate into a fading group and a steady group. The present census split does not count, since it predates any such change.

## B. Refined kinds

Limits a better model outgrows (step-by-step playbooks, perhaps generated maps); limits of the setting (restart, compaction, the working context, while sessions start without memory); the record; the User's gates; guardrails against model error and conventions as possible further kinds.

- **For:** gives each kind a criterion that fits it; separates what should fade on a short clock from what should wait for a change in the setting.
- **Against:** the split is fitted to the census, which supports a verdict on one part only; the guardrail and convention kinds have no census evidence (claim-status and the language standard are beyond its reach); the boundary moves as context windows grow; mixed parts need a rule for several kinds.
- **What would show it wrong:** a without-the-part trial on a unit sorted as a limit of the setting succeeds, or at a re-run after a model change units of that kind decline like the outgrowable ones. A re-run on the same estates is weak confirmation.

## C. A different axis: how a part is kept

The controls model's ladder (block, ask, advise, watch, written guidance), with each part placed on it.

- **For:** it fits the census at least as well as B. The persisting parts mostly have mechanical teeth (the spawn-tier gate, the automated compaction marker and restart, scripted doctor checks, the confidentiality sweep), and the part that fades is written guidance. KILLED_MECHANISMS shows the test "does this rule need judgement, or can a script detect it" predicting which enforcement attempts failed. Enforced parts can be switched off for a cheap trial (shadow-first).
- **Against:** the ladder describes a part's mechanism, and whether a better model needs the part takes its own test. Hook telemetry is thin, so enforced parts are less measurable today than this option assumes.
- **What would show it wrong:** a part's place on the ladder shows no relation to how it holds up across a model change, or to how cheaply it can be trialled.

## D. No sort: a failure criterion for every part

Apply the existing stage rule to all 32 parts.

- **For:** uses a rule the framework already has; avoids drawing kinds wrong; every part becomes falsifiable; one census re-run reviews every unit at once, and units can be ordered by testability.
- **Against:** loses the strategic reading the User asked about (what to expect to retire); eight parts have no census signature, so their criteria are untestable now.
- **What would show it wrong:** criteria for the measurable parts produce no decision at their first review.

## E. Trial first, no taxonomy

Run a without-the-part trial where the evidence points (step-by-step playbooks), and widen only on its result, as "tools added on evidence" asks.

- **For:** the smallest step the evidence supports, and it tests need directly.
- **Against:** one part at a time gives no framework-wide reading; trials cost sessions.
- **What would show it wrong:** the playbook trial is inconclusive, and the next candidate cannot be chosen without a sort.

## F. An assumption register keyed to model releases

Each part records the model behaviour it assumes (for example "sessions start without memory", "the model does not plan multi-step work unprompted"). Review fires when the working model changes.

- **For:** the one option that tests the Bitter Lesson claim directly, since the claim is about model change; it uses the release cadence the tier map already tracks.
- **Against:** writing a true assumption for each part takes judgement, and some parts assume nothing about the model (the record, the User's gates).
- **What would show it wrong:** a model change arrives and no stated assumption can be checked against it.

## G. Prescribed procedure, or judgement practice

Sort each part by what it asks of the model: a prescribed sequence of steps (step-by-step playbooks, runbook steps), or a practice that calls for judgement and leaves its form to the model (planning, delegated review, keeping the record, routing).

- **For:** it is the split the model-generation evidence shows at the one switch measured: prescribed steps fell and judgement practices rose. It predicts a direction for each unit, which gives it a testable expectation at every model change.
- **Against:** one switch in one estate, small samples, and the switch coincides with time passing and the User's own practice changing. Two readings complicate it: proportion's named agents fell under Opus 5, and rooms' Fable 5.1 sessions made few working-context edits. Some parts are both (a plan template prescribes sections and calls for judgement inside them).
- **What would show it wrong:** at the next model change, judgement practices fall alongside prescribed procedure, after correcting for activity.

## Variants

- B or A with C as a second tag (a column), deciding which test type each unit gets.
- B with D: B decides what each criterion tests; every unit gets a criterion.
- F with E: assumptions keyed to releases, with the playbook trial as the first test.
- F with E and G: as above, with G setting each unit's expected direction at a model change.

## The session's lean, stated to be challenged

The census pattern fits B and C alike; the longitudinal view adds a direction that G names. Step-by-step playbooks, built in 2025 for named model failures by the scout readings, fell from six named to one across four model generations in proportion and fell again in rooms at the latest switch, with proportion's falling activity as a confound. Practices calling for judgement rose at the one switch measured. Because the Bitter Lesson's trigger is a model change, and telemetry dates each change, the lean is **F with G**: each unit records the model behaviour it assumes and whether it prescribes steps or calls for judgement; review fires at each model change, expecting prescribed procedure to fade and judgement practice to hold or grow. **E** is aimed at the remaining planning playbook (does it add anything beyond the planning rules), since the wider playbook decline has already happened in practice. C's ladder could tag each unit to choose its test type. The lean would change if, at the next model change, judgement practices fell with procedure (against G), or if the planning-playbook trial showed the playbook carrying weight the rules do not (favouring a finer unit).
